Auto IVTC

In your episode folder, you'll need:
- Step1.py, Step2.py and Step3.py (copied from this folder)
- The episode's .mov file

The episode folder (or a folder above it) must have the episode number in its name as S##E##, for example "S03E01 The Search Part 1".

If a script fails, the window stays open showing the error, and the error is also saved to Step1_error.txt, Step2_error.txt or Step3_error.txt in the episode folder. The next successful run of that script deletes the file.

1. Run python Step1.py

What this does:
It finds the .mov file in the folder. If there is one, it asks you to confirm it; if there are several, it asks which one to use. It then creates these files with the MOV file and episode number filled in:

- S##E## DI.avs - A reference script that uses QTGMC in draft mode for determining frame numbers to use to replace orphaned fields.

- S##E## IVTC.avs - The main inverse telecine script that is used for most of the episode

- S##E## RifeGen.avs - Script that produces frames or ranges generated by RIFE

- S##E## Mapping.avs - Reference script that visualizes all 5 pulldown cadences and QTMC in draft mode, for finding correct cadences for ranges where AutoIVTC misidentifies

- S##E## 60p_EndCred.avs - produces the ending credits deghosted and in QTGMC-deinterlaced 60p, add the start and end frames from S##E## DI.avs in Trim()

- S##E## 24p_OutroCred.avs - Deghosts the outro credits, add start and end frames from S##E## IVTC.avs in Trim() and then mask in

- S##E## 24p_PostIntroCred.avs - Deghosts the credits after the opening titles, add start and end frames from S##E## IVTC.avs in Trim() and then mask in

- Scenes.avs - reference script that uses QTGMC in draft mode and cut to 23.976 fps, as well as the scene edit detection with indicator on screen, for identifying frames to use as Breaks as well as spot checking the ranges in frame_analysis.xlsx

- Breaks.txt - using Scenes.avs, add frames to mark the ends and/or beginnings of fade-ins and/or fade-outs or cross-dissolves where scene edit detection would fail

- DIMap.txt - add frame numbers or ranges in S##E## IVTC.avs and the frame numbers or ranges to replace them with in S##E## DI.avs, result will be reflected in S##E## IVTC.avs

- IVTCDIMap.txt - add frame numbers or ranges S##E## IVTC.avs to be processed by QTGMC lossless

- PD2Map.txt, PD3Map.txt, PD4Map.txt, PD5Map.txt - frame mappings for the difference pulldown cadences

- RIFEGenMap.txt - add frame numbers or ranges in S##E## IVTC.avs to be replaced by S##E## RifeGen.avs, result will be reflected in S##E## IVTC.avs

- RIFEMap.txt - add frame ranges to be interpolated from 29.97p to 23.976p by RIFE

If any of the .avs scripts already exist, it asks before overwriting them. Text files that already exist are never touched.

2. Fill in Breaks.txt - This is a list of the first frame of each fade-in from the black of the commercial breaks. The script will insert these as starting frames for scenes where edits can't be detected because of the fades. Use Scenes.avs to scrub through the episode, determine where each of these starting points are, write those frame numbers to Breaks.txt and save.

3. Run python Step2.py

What this does:
This analyzes the full video 5 times, 1 for each pulldown cadence. Using combing detection, it determines if a frame is combed or not. It then creates an Excel sheet as follows:
Column A - Frame number
Column B - PD1 - if combed, 0, if clean, 1
Column C - PD2 - if combed, 0, if clean, 1
Column D - PD3 - if combed, 0, if clean, 1
Column E - PD4 - if combed, 0, if clean, 1
Column F - PD5 - if combed, 0, if clean, 1

It then analyzes the video using motion-estimated scene edit detection logic (which you can see in Scenes.avs). It uses QTGMC and TDecimate to avoid combing being an issue for scene detection. It also marks a scene change wherever the frame-to-frame luma difference jumps to at least 3 times that of the frames on either side, which catches cuts in dark scenes that the motion-based detection misses (Scenes.avs only shows the motion-based detection). To turn this off, run python Step2.py --spike-ratio 0; a higher number makes it stricter. The frame ranges are written to a second sheet in the Excel file. Everything before the first break becomes a single range, and everything from the last break to the end becomes a single range.

4. Open frame_analysis.xlsx and go to the Scene Ranges sheet. The 3rd column already holds the range length (=B-A), and any range shorter than 20 frames is highlighted in light red; spot check those. Make any corrections and save.

5. Run python Step3.py

What this does:
First it checks that Scenes.avs and S##E## IVTC.avs (and everything they load) open. If one doesn't, it stops with the AviSynth error before changing anything.

Using the frame ranges from Scene Ranges, it adds the comb detection values from the Frame Analysis sheet together within those ranges for each pulldown cadence. The Cadence with the highest value is the winner. In the case of a tie, the first one wins. So for example if PD2 and PD3 are equal, PD2 wins. If PD5 and PD1 are equal, PD5 wins.

The ranges are written respectively to each winning cadences mapping file (PD1Map.txt, PD2Map.txt, etc.)

Then it uses scene edit detection on QTGMC without TDecimate, and writes whether or not an edit is detected to a 3rd sheet in the excel file. For each frame, using luma difference, it attempts to determine if that frame or the frame before it is an orphaned field and keeps that one.
Then it uses comb detection on your S##E## IVTC.avs script as it currently stands and matches those frames up with the deinterlaced orphaned fields to create DIMap.txt.

6. You can now scrub through the whole episode and make any needed corrections to the mapping files as well as addressing any other issues as you see fit.
